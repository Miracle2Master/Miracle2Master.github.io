# 面试真题&口述回答稿


#### 2. Java 中 super 关键字有哪些主要用途？请结合类继承的场景进行说明。

回答：super主要有三个用处。第一个，在子类的构造方法里调用父类的构造函数，就像我唐山港项目里，货物单据的子类继承一个基础单据父类，用super去初始化单据编号、创建时间这些公共字段，不用重复写代码。第二个，当子类和父类有同名的成员变量的时候，可以用super拿到父类里面那个变量的值。第三个，子类重写了父类的方法之后，可以用super调用父类原来的方法。比如说我先执行父类通用的参数校验，再加上子类自己独有的校验逻辑。

#### 3.结合你简历中提到的 Java 多线程技能，简要解释 synchronized 关键字在 Java 中的作用，并说明它在实例方法和静态方法上使用时所锁的对象分别是什么。

回答：synchronized是Java里面的内置锁，用来处理多线程并发竞争的问题，保证代码执行的原子性、可见性，避免出现库存超卖、数据互相覆盖这类问题。如果修饰普通的实例方法，锁的是当前this实例对象，不同实例之间互不影响。如果修饰静态方法，锁的是这个类的Class对象，属于全局锁，适合像库存总量统计这种需要全局互斥的场景，我实习里面统计库存的时候就用到过。

#### 4. 在一个支持多用户协作的桌面客户端应用中，数据会定期同步到中心数据库。为了追踪每条数据的来源和变更历史，除了常规的业务字段外，还需要设计哪些审计相关的字段，并说明这些字段在数据同步过程中应如何保持一致性。

回答：审计字段我会加上创建人ID、创建时间、最后更新人ID、最后更新时间、版本号、客户端唯一标识、变更流水号，还会加上逻辑删除标记。同步的时候依靠版本号做乐观锁，更新之前比对版本，防止旧数据覆盖新数据；用变更流水号做幂等，重复同步的时候直接跳过，避免重复写入。业务数据和审计字段放在同一个事务里面，一起成功一起回滚。如果多端发生冲突，以中心数据库为准，保证全局数据一致。

#### 5. 如何安排时间节点控制质量的吗？针对近两年的项目。

回答：我会把项目拆成一个个里程碑迭代，优先保证核心逻辑自测。拿唐山港这个实习项目来说，我拆成表结构设计、状态流转开发、并发逻辑开发、联调测试、上线这几个阶段。每一个迭代做完，我都会优先自测库存并发、状态机流转这些核心逻辑，核心链路没问题再往下走。高优先级的bug优先处理，不会带着严重问题继续开发，次要需求可以往后放，不会为了赶进度牺牲核心功能的稳定性。

#### 6. 这个项目最终交付后取得了怎样的具体成果或反馈？

回答：上线之后，之前库存超卖、并发数据不一致的问题彻底解决了。整条货物入库、转运、出库的状态链路都可以完整追溯，满足港口台账审计的需求。接口在并发场景下运行稳定，没有出现卡顿。我们这个模块里面状态机、幂等处理的方案，后面团队别的业务模块也拿来参考，测试反馈这个模块线上缺陷很少，达到交付要求。

#### 7.能否再分享一个近期遇到的复杂事情，说说你是如何推进并解决的？

回答：我讲一下科研资料RAG系统遇到的检索漂移、大模型幻觉的问题。当时系统经常召回很多无关的文档片段，大模型容易脱离文档编造内容，Function Calling也会频繁误触发。我先定位到两个原因，一是向量召回的噪声比较大，二是提示词约束不够，工具调用缺少前置判断。后面我增加了重排模型，对召回的结果二次筛选，过滤相关性低的段落；同时加了意图判断，只有真正需要查资料库的时候才调用检索工具；并且在提示词里面明确约束，找不到原文信息就如实说明，不允许编造。优化之后幻觉、答非所问的情况明显变少，检索精准度提升，能够稳定支撑课题组查阅文献。

#### 8. 如何平衡时间和重要，可以围绕你近两年最漂亮的项目。
回答：我拿RAG这个科研资料系统来说。拿到需求之后，我首先区分哪些是核心、哪些是次要。核心就是文档解析入库、向量检索、问答链路、Function Calling还有幻觉治理，这是项目最有价值的地方，我把大部分时间放在这一块，还专门留出调优的窗口，不会压缩验证自测的时间。像页面美化、高级筛选、导出拓展这类属于次要功能，我放到后面迭代。我用小里程碑推进，每一轮只保证核心链路可跑可验证。当时也有人建议我先把所有功能做完再调效果，我权衡之后还是优先稳住核心问答能力，次要功能等核心稳定之后再慢慢补上，保证最重要的目标先落地。
