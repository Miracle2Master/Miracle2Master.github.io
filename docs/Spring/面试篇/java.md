## 一、概念

1. 说一下 Java 的特点？

   Java 有三个核心特点。第一是平台无关性，源码编译成字节码，由 JVM 翻译成机器码，做到一次编写到处运行；第二是纯面向对象，几乎一切皆对象，支持封装、继承、多态；第三是内存管理自动化，有垃圾回收，开发者不用手动释放对象。另外还可以提多线程支持、生态成熟、安全性好。

2. Java 的优势和劣势是什么？

   优势是跨平台，JVM 屏蔽了系统差异；生态庞大，Spring 等框架和类库齐全；自动垃圾回收降低了内存泄漏风险；内置多线程；企业级应用长期使用，稳定性和向后兼容做得好。劣势是相比 C++、Rust 有 JVM 开销，启动慢，微服务场景不如 Go 轻；语法样板代码多；JVM 自身占内存；面向对象过于严格，写简单程序反而繁琐。

3. Java 为什么是跨平台的？

   关键在于 JVM。Java 源码被 javac 编译成与平台无关的字节码 .class 文件，不同平台安装各自版本的 JVM，由 JVM 把字节码翻译成本平台机器码执行。要强调跨平台的是 Java 程序，不是 JVM，JVM 本身是 C/C++ 写的本地程序，必须按平台安装不同版本。

4. JVM、JDK、JRE 三者关系？

   范围是 JDK 包含 JRE，JRE 包含 JVM。JVM 是运行字节码的虚拟机，负责解释/JIT 执行和内存管理；JRE 是运行环境，等于 JVM 加核心类库；JDK 是开发工具包，等于 JRE 加 javac、jdb 等开发工具。开发要装 JDK，只运行程序装 JRE 就够。

5. JVM 和 Java 有啥区别？

   Java 是编程语言，提供语法和类库；JVM 是运行 Java 程序的虚拟机平台，负责把编译后的字节码翻译成机器指令执行。两者分工不同，一个是写代码的工具，一个是跑代码的环境。补充一点，JVM 不只能跑 Java，Kotlin、Scala 编译成字节码同样能运行。

6. 为什么 Java 解释和编译都有？

   分两步。第一步编译，javac 在程序运行前把源码整体编译成平台无关的字节码；第二步在 JVM 里，先用解释器逐条解释执行字节码，同时通过方法调用计数器和回边计数器识别热点代码，达到阈值后由 JIT 编译成本地机器码缓存在 Code Cache 中，后续直接执行机器码。所以 Java 是解释器和 JIT 混合的模式。

7. JVM 是什么？

   JVM 是 Java 虚拟机，主要工作是把字节码指令映射到本地 CPU 指令和操作系统调用。它屏蔽了与操作系统平台相关的信息，使得同一份字节码可以在多种平台上不加修改地运行，这也是 Java 一次编译到处运行的原因。

8. 编译型语言和解释型语言的区别？

   编译型语言在程序执行前把整个源码编译成目标平台的机器码，生成可执行文件，执行快但跨平台差，典型是 C、C++。解释型语言在运行时逐行解释执行源码，不生成独立可执行文件，跨平台好但速度相对慢，典型是 Python、JavaScript。Java 属于两者混合：先编译成字节码，再由 JVM 解释加 JIT 执行。

9. Python 和 Java 区别是什么？

   Java 是编译与解释混合执行：源码先被 javac 编译成字节码，再由 JVM 用解释器加 JIT 执行；它是静态强类型，性能好，适合大型工程。Python 是解释型语言，运行时由解释器逐行翻译执行，虽然 CPython 内部也会先编译成 .pyc 字节码，但整体执行模型仍是解释执行；它是动态类型，开发效率高，性能相对低。

10. 值传递和引用传递的区别？

    Java 只有值传递，不存在真正的引用传递。基本类型传的是实际值的副本，方法内修改副本不影响原变量；引用类型传的是对象引用的副本，副本和原引用指向同一个对象，所以通过副本修改对象内部数据会影响原对象，但给副本重新赋值、让它指向新对象，不会改变原引用的指向。

## 二、数据类型

1. 八种基本的数据类型？

   分三类：数值型有 byte（1 字节）、short（2 字节）、int（4 字节）、long（8 字节）、float（4 字节）、double（8 字节）；字符型 char（2 字节，Unicode）；布尔型 boolean（没有明确字节数，理论上 1 位）。默认值方面，boolean 是 false，char 是 '\u0000'，数值类型都是 0 或 0.0。浮点数默认是 double，整数默认是 int，long 常量要加 L，float 常量要加 f。

2. int 和 long 是多少位，多少字节？

   int 是 32 位、4 个字节，有符号，范围 -2^31 到 2^31-1，超过约 21 亿会溢出；long 是 64 位、8 个字节，有符号，范围 -2^63 到 2^63-1，用于表示很大的整数，比如文件大小。

3. long 和 int 可以互转吗？

   可以。int 转 long 是自动转换，范围变大所以安全；long 转 int 必须强制类型转换，超出 int 范围时只保留低位，会发生数据丢失或溢出，转换前最好先做范围检查。

4. 数据类型转换方式你知道哪些？

   四种：自动类型转换，小范围转大范围，Java 自动完成；强制类型转换，大范围转小范围，可能溢出或精度损失；字符串转换，用 Integer.parseInt、Double.parseDouble 等；包装类提供的数值转换，比如 Integer.toHexString、Character 相关方法。

5. 类型互转会出现什么问题？

   基本类型方面，大范围赋给小范围会溢出，比如 int 300 强转 byte 只保留低 8 位得到 44；浮点转整数会丢小数，比如 3.14 转 int 得到 3。引用类型方面，向上转型自动且安全；向下转型要强制转换，如果对象实际类型不匹配就抛 ClassCastException，所以转型前要用 instanceof 判断。

6. 为什么用 BigDecimal 不用 double？

   double 是二进制浮点数，无法用有限位数精确表示 0.1 这类十进制小数，只能存近似值，计算会出误差，比如 0.1 加 0.2 得到 0.30000000000000004，金额场景不能接受。BigDecimal 用任意精度整数加 scale 表示十进制数，能精确计算。要注意四点：用字符串构造而不是直接传 double；除法必须指定精度和舍入模式，否则除不尽会抛 ArithmeticException；比较数值用 compareTo 等于 0，equals 会连 scale 一起比；BigDecimal 不可变，add 等方法返回新对象，要接住返回值。

7. 装箱和拆箱是什么？

   是基本类型和包装类之间的转换。装箱如 Integer i = 10，编译后是 Integer.valueOf(10)；拆箱如 int n = i，编译后是 i.intValue()。自动装箱常发生在赋值、方法调用传参和返回值时。主要弊端是在循环里做自动装箱会创建大量对象，比如用 Integer 变量做累加，每次 sum += i 都是拆箱相加再装箱，超出缓存范围就会新建大量对象，加重 GC 负担。

8. Java 为什么要有 Integer？

   三个作用。一是适配集合和泛型，泛型参数只能是引用类型，不能写 `List<int>`，只能写 `List<Integer>`；二是能表示 null，用来区分没有值和值为 0，比如用户年龄未填写；三是提供处理整数的工具方法，如 parseInt、toString、toHexString，这些都是静态方法，不用创建对象。要注意 Integer 为 null 时自动拆箱会抛 NullPointerException。

9. Integer 相比 int 有什么优点？

   Integer 是引用类型，可以放进集合和泛型，可以赋 null 表达空值，支持自动装箱拆箱让类型转换更方便，还提供了一批工具方法。代价是需要为对象分配内存、读写效率低于 int，并且可能因为 null 拆箱触发空指针异常。

10. 那为什么还要保留 int 类型？

    因为效率和内存。基本类型的变量内存块直接存数据本身，读写比引用类型快；64 位 JVM 开启引用压缩时，一个 Integer 对象占 16 字节，而 int 只占 4 字节，空间占用差 4 倍。所以普通数值计算、循环计数优先用 int，避免不必要的装箱拆箱。

11. 说一下 Integer 的缓存？

    Integer 内部有 IntegerCache，用 Integer.valueOf 创建对象时会先判断值是否落在缓存范围内，命中就直接复用缓存对象。默认缓存 -128 到 127，下限固定，上限可以通过 JVM 参数调整。所以 Integer a = 127 和 Integer b = 127 用 == 比是 true，但 128 和 128 在默认范围下是 false，用 equals 才是 true。自动装箱调用的是 valueOf，所以也用缓存；显式 new Integer 不走缓存，而且这个构造器从 Java 9 起已过时。Integer 和 int 比较时 Integer 会先拆箱比数值，但如果它是 null 就会抛空指针。实际开发比较两个 Integer 的数值用 equals 或 Objects.equals，不能靠缓存范围来决定用 ==。

## 三、面向对象

1. 怎么理解面向对象？简单说说封装继承多态。

   面向对象是把现实事物抽象成对象，对象有属性（字段）和行为（方法），程序通过对象之间的交互完成功能。三大特性：封装是把数据和操作数据的方法结合，对外隐藏内部细节，只暴露接口，增强安全性和独立性；继承是子类自动共享父类的属性和方法，实现代码复用和清晰的层次结构；多态是同一个接口、不同实例执行不同操作，分编译时多态（重载）和运行时多态（重写），提升灵活性和扩展性。

2. 多态体现在哪几个方面？

   四个方面。方法重载，同一个类中同名但参数列表不同，编译期就确定调用哪个；方法重写，子类提供父类同名方法的新实现，运行时按对象实际类型决定，这是多态最主要的体现；接口与实现，多个类实现同一接口，用接口引用调用时触发各自实现；向上转型和向下转型，父类引用指向子类对象可以运行时替换实现，向下转型前要先判断实际类型避免 ClassCastException。

3. 多态解决了什么问题？

   提高代码的扩展性和复用性，让子类可以替换父类，调用方面向抽象编程而不依赖具体实现。它是策略模式、基于接口而非实现编程、依赖倒置原则、里氏替换原则、用多态去掉冗长 if-else 等设计原则和技巧的实现基础。

4. 面向对象的设计原则你知道有哪些吗？

   六大原则：单一职责，一个类只负责一项职责，只有一个引起它变化的原因；开放封闭，对扩展开放、对修改关闭；里氏替换，子类对象应该能替换掉所有父类对象；接口隔离，接口要小而专，客户端不依赖它不需要的接口；依赖倒置，高层和低层都依赖抽象，抽象不依赖细节；最少知识（迪米特），一个对象对其它对象了解最少，只和直接朋友交互。

5. 重载与重写有什么区别？

   重载是同一个类（包括继承得到的）中方法名相同、参数的类型或个数或顺序不同，编译器在编译期根据参数和声明类型决定调用哪个，不能只靠返回类型不同来重载。重写是子类对父类可重写的实例方法提供新实现，方法名和参数列表一致，运行时由 JVM 按对象实际类型决定执行哪个。重写的限制：返回类型可以协变，访问权限不能比父类更严格，不能扩大受检异常，final 方法不能重写，private 方法不被继承，static 方法是隐藏不是重写。@Override 不是必要条件，但建议加，避免参数写错变成重载。

6. 抽象类和普通类区别？

   抽象类不能被实例化，只能被继承，方法可以有实现也可以只有声明，通常作为基类被扩展；普通类可以直接实例化，方法都要有具体实现。继承规则上两者完全一样，都只能单继承，都可以实现多个接口。抽象类可以有构造器，供子类初始化时调用。

7. Java 抽象类和接口的区别是什么？

   抽象类用 extends 继承，一个类只能继承一个，可以有成员变量（含实例变量）、构造方法和具体方法，适合有明显继承关系、需要复用代码的场景。接口用 implements 实现，可以多实现，成员变量默认 public static final 必须是常量，方法默认 public abstract，Java 8 起可以有 default 和 static 方法，Java 9 起可以有 private 方法，适合定义行为规范或能力。接口是实现多重继承的间接手段。

8. 抽象类能加 final 修饰吗？

   不能。抽象类存在的意义就是被继承，而 final 修饰符的作用是禁止类被继承，两者互斥，同时使用会编译不通过。

9. 接口里面可以定义哪些方法？

   四类。抽象方法，是接口的核心，默认 public abstract，实现类必须实现；默认方法 default，Java 8 引入，接口可以提供具体实现，实现类可以选择重写；静态方法 static，Java 8 引入，属于接口本身，通过接口名直接调用；私有方法 private，Java 9 引入，只能在接口内部使用，用于给 default 方法做辅助实现。

10. 抽象类可以被实例化吗？

    不能直接用 new 创建抽象类对象。但抽象类可以有构造器，子类实例化时会通过 super 调用它完成抽象类那部分初始化。所以严格说是创建了实现了全部抽象方法的子类对象，间接用到了抽象类的构造器，不是抽象类本身被实例化。

11. 接口可以包含构造函数吗？

    不可以，编译器会报 Interfaces cannot have constructors。构造器的作用是在 new 的一瞬间初始化实例，而接口不能被实例化，没有实例可初始化，也就没有调用场景。

12. 解释 Java 中的静态变量和静态方法

    静态变量属于类不属于实例，内存中只有一份、被所有对象共享，类加载时初始化一次，推荐用类名点变量名访问，常用于常量、计数器这类共享数据，改一个实例看到的都是新值。静态方法属于类，不用创建对象就能调用，不能直接访问非静态成员，因为静态方法没有实例上下文，但可以直接调用其他静态成员；常用于工具方法如 Math.random、工厂方法。静态方法不支持重写，子类同名同参数的静态方法属于隐藏。

13. 非静态内部类和静态内部类的区别？

    非静态内部类依赖外部类实例，必须先有外部类对象才能创建，可以直接访问外部类的所有成员，Java 16 之前不能定义静态成员。静态内部类不依赖外部类实例，可以独立创建，只能直接访问外部类的静态成员，访问实例成员需要先拿到外部类实例引用，可以定义静态成员。两者都能访问外部类的私有成员，区别在于静态内部类访问私有实例成员时必须有外部类实例。需要和外部实例无关时用静态内部类，可以避免内部类持有外部类引用导致的内存泄漏。

14. 非静态内部类可以直接访问外部方法，编译器是怎么做到的？

    编译器在生成非静态内部类时会为它维护一个指向外部类实例的引用，通常在字节码里叫 this$0，并在内部类的构造方法中把外部类实例作为参数传入，实例化时建立两者的关联，所以内部类能直接访问外部类的实例变量和方法。

## 四、关键字

1. Java 中 final 作用是什么？

   修饰类不能被继承，比如 String 就是 final 类；修饰方法不能被子类重写，但可以正常继承和调用，也可以重载；修饰变量只能赋值一次，局部变量使用前必须赋值，final 实例字段可以在声明、实例初始化块或构造方法中赋值。要注意两点：final 修饰引用只保证不能改指向，对象内部数据仍然可以修改；类被 final 修饰也不代表对象不可变。String 不可变除了类 final 之外，更关键的是它把内部存储封装起来、不提供修改自身内容的方法、构造和对外传递时避免了直接暴露内部数组，设计不可变对象不能只加一个 final。

2. Java 中 static 的作用是什么？

   四种用法。修饰变量：属于类，全类共享一份，类加载时初始化，用类名访问；修饰方法：属于类，不用创建对象就能调用，不能直接访问非静态成员，常用于工具方法和工厂方法；修饰代码块：在类初始化阶段执行且只执行一次，早于对象构造，多个按定义顺序执行；修饰内部类：静态内部类不依赖外部类实例，可独立创建，适合和外部实例无关的场景。

## 五、深拷贝和浅拷贝

1. 深拷贝和浅拷贝的区别？

   浅拷贝只复制对象本身和其中的基本类型字段，引用类型字段复制的是引用地址，新旧对象仍然指向同一个内部对象；深拷贝会递归复制所有引用类型字段的内容，生成全新的对象以及其内部的所有对象，两个对象完全独立。

2. 实现深拷贝的三种方法是什么？

   一是实现 Cloneable 接口并重写 clone，在 clone 中对每个引用字段再递归调用 clone；二是序列化和反序列化，要求对象和所有引用字段都实现 Serializable，通用性好但性能有损耗；三是手动递归复制，为每层对象单独写 copy 方法，结构不复杂时最直观也最可控。

## 六、泛型

1. 什么是泛型？

   泛型是在定义类、接口或方法时先用一个类型参数表示具体类型，使用时再指定，比如 `List<String>`。它解决两个问题：代码复用，一个 `Box<T>` 就能适配各种类型，不用分别写 StringBox、IntegerBox；类型安全，把类型检查提前到编译期，取出来不用强制转换，避免 ClassCastException。泛型通过类型擦除实现：编译期做类型检查，生成字节码时把类型参数替换成上界（没指定上界就是 Object），并在需要处插入转换，所以 `List<String>` 和 `List<Integer>` 运行时是同一个类，instanceof 对比也是 true。两个注意点：类型参数只能是引用类型，不能写 `List<int>`；`List<Integer>` 不是 `List<Number>` 的子类，需要按读写需求用通配符，读用 `? extends Number`，写用 `? super Integer`。

## 七、对象

1. Java 创建对象有哪些方式？

   常见五种。new 关键字，最基础最常用，调用构造器，缺点是紧耦合具体类名；反射，用 Class 或 Constructor 的 newInstance 动态创建，Class.newInstance 从 JDK 9 起过时，推荐 Constructor.newInstance，框架里常用；clone，实现 Cloneable 并重写 clone，基于原型复制，默认是浅拷贝；反序列化，从字节流恢复对象，不会调用构造器，类必须实现 Serializable；工厂方法，把 new 封装在方法里，如 Integer.valueOf、Calendar.getInstance，能隐藏创建逻辑和控制实例。

2. Java 创建对象除了 new 还有别的什么方式？

   还有反射、反序列化、clone，以及工厂方法。反射能在运行时按类名动态创建，解耦且灵活，Spring 的 IOC 就是典型；反序列化从字节流重建对象，用于持久化和网络传输；clone 基于已有对象生成副本，需要实现 Cloneable；工厂方法是对 new 的封装，可以加缓存、池化等逻辑。

3. new 出的对象什么时候回收？

   由垃圾回收器负责。判断标准是可达性分析：从 GC Roots 出发沿引用链遍历，能到达的对象存活，不能到达的才成为回收候选。常见 GC Roots 有活动线程栈中的引用、已加载类的静态字段引用、JNI 全局引用。两个对象互相引用但整体不可达时仍然能回收，所以不是引用计数。不可达之后也不保证马上回收，取决于 GC 触发时机和回收器策略；System.gc() 只是请求不保证立即执行。另外文件、数据库连接、Socket 这类资源要用 close 或 try-with-resources 释放，不要依赖 finalize，它执行时机不确定，Java 18 起已被标记为待移除。

4. 如何获取私有对象？

   两种方式。一是通过类提供的公共 getter 方法，这是规范做法，简单安全；二是通过反射，用 getDeclaredField 拿到私有字段后 setAccessible(true) 关闭访问检查再 get，可以绕过 private，但 Java 9 模块系统下如果包没有对外开放仍可能受限。

## 八、反射

1. 什么是反射？

   反射是在程序运行时获取类的结构信息，并动态创建对象、调用方法、访问字段的机制。核心围绕 Class 对象展开，用 Constructor 调用构造方法创建对象、Method 调用方法、Field 读写字段。适合编译时不知道具体类、需要按配置动态处理的场景，比如根据配置文件里的类名加载类。

2. 反射能随意访问私有成员吗？有什么代价？

   不能说完全没有限制。getMethod 只获取 public 方法包括继承来的，getDeclaredMethod 获取当前类声明的方法包括 private 但不含继承的；能拿到方法信息不代表有权限调用，访问私有成员通常要 setAccessible(true) 尝试关闭语言层面的检查，但仍受权限和模块封装限制，final 字段的修改也有额外约束。代价是检查推迟到运行时，类名方法名写错要到运行才报错，并且有访问检查和动态调用的成本。所以反射适合框架和通用工具，普通业务代码优先直接调用，频繁使用时应缓存 Class、Method。

3. 反射在你平时写代码或者框架中的应用场景有哪些？

   三个典型场景。一是加载数据库驱动，用 Class.forName 按配置传入不同驱动类，比如 MySQL 或 Oracle 的驱动；二是 Spring 的 IOC，解析 XML 或注解拿到类名字符串，再反射创建 Bean、注入属性；三是框架通用能力，比如 ORM 把数据库记录映射成对象、动态代理、注解解析、JSON 序列化和反序列化。

## 九、注解

1. 能讲一讲 Java 注解的原理吗？

   注解本质是一个继承了 Annotation 的特殊接口，它的具体实现类是 Java 运行时生成的动态代理类。我们通过反射获取注解时，拿到的是这个动态代理对象；通过代理调用注解的方法，最终会进入 AnnotationInvocationHandler 的 invoke 方法，从 memberValues 这个 Map 里按方法名索引出对应的属性值，而 memberValues 的数据来源是常量池里的注解信息。

2. 对注解解析的底层实现了解吗？

   注解编译后会变成继承 Annotation 的接口。按保留策略分三类：SOURCE 只存在于源码，编译后丢弃；CLASS 保留在 class 文件里但运行时不可见；RUNTIME 保留在 class 文件并能在运行时通过反射访问，只有这种能解析。RUNTIME 注解的信息存在 class 文件属性表的 RuntimeVisibleAnnotations 等结构中，可以用 javap -v 查看。解析依赖反射：以 Class.getAnnotation 为例，内部会触发注解数据的延迟解析，通过 AnnotationParser 读取 JVM 在类加载阶段抽取的原始字节，反序列化成 Map，最后以动态代理对象返回。JVM 底层负责读取常量池和属性表，getAnnotation 这一层是纯 Java 实现。

3. Java 注解的作用域呢？

   作用域由元注解 @Target 配合 ElementType 指定，Java 21 共有 12 种：TYPE 类接口枚举注解、FIELD 字段、METHOD 方法、PARAMETER 参数、CONSTRUCTOR 构造方法、LOCAL_VARIABLE 局部变量、ANNOTATION_TYPE 注解类型本身、PACKAGE 包、TYPE_PARAMETER 泛型类型参数、TYPE_USE 任何使用类型的地方、MODULE 模块、RECORD_COMPONENT 记录类组件。最常用的是 TYPE、FIELD、METHOD、PARAMETER。不显式写 @Target 时，默认可以用于除 TYPE_PARAMETER 和 TYPE_USE 外的所有位置。

## 十、异常

1. 介绍一下 Java 异常

   顶层是 Throwable，分两个子类。Error 表示运行环境的严重错误，程序无法处理也不应尝试捕获，比如 OutOfMemoryError、StackOverflowError。Exception 表示程序可以处理的异常，又分两类：受检异常是编译期必须捕获或声明抛出的，通常是外部问题，如 IOException、FileNotFoundException、ClassNotFoundException；运行时异常是 RuntimeException 及其子类，由程序逻辑错误导致，编译期不强制处理，如 NullPointerException、ArrayIndexOutOfBoundsException。运行时异常和 Error 合起来叫非受检异常。

2. Java 异常处理有哪些？

   五类机制。try-catch 捕获并处理，多个 catch 要把具体的异常类型放前面、范围大的放后面，否则父类会提前接住子类；throw 在方法体内主动抛出异常对象，throws 在方法签名上声明该方法可能抛出的受检异常；finally 执行清理逻辑，正常结束、抛异常、return 通常都会执行，但 JVM 退出或进程被强杀时不保证，不要在 finally 里写 return，会覆盖返回值甚至吞掉异常；try-with-resources 自动关闭实现 AutoCloseable 的资源，多个资源按声明相反顺序关闭，业务异常保留为主异常、关闭异常作为 suppressed 附加，可以用 getSuppressed 查看。实际开发中避免空 catch，能处理就给恢复逻辑，不能处理就向上抛并保留原始 cause。

3. 抛出异常为什么不用 throws？

   两种情况。一是非受检异常，也就是继承自 RuntimeException 或 Error 的异常，编译器不强制要求声明；二是异常在方法内部已经被捕获并处理了，不需要再交给调用方。只有受检异常且方法自己不处理时，才必须用 throws 声明。

4. try catch 中的语句运行情况

   try 里的代码按顺序执行，一旦某句抛出异常，该句之后的代码不再执行，直接跳到匹配的 catch 块处理；catch 执行完后继续执行 catch 之后的代码；如果没有匹配的 catch，异常就向上一层调用方法传播。

5. try{return "a"} finally{return "b"} 这条语句返回啥

   返回 "b"。finally 块里的 return 会覆盖 try 块里的 return 返回值。实际开发中不要在 finally 里写 return，它还可能把原本要传播的异常吞掉。

## 十一、Object

1. Object 类有哪些方法？

   11 个核心方法。equals 默认比较内存地址；hashCode 返回哈希码，和 equals 要配套重写；toString 默认返回类名加 @ 加哈希十六进制，实际开发常重写用于日志调试；getClass 返回运行时实际类对象，不能重写，反射常用；clone 创建浅拷贝，需要实现 Cloneable 否则抛 CloneNotSupportedException；wait 有三个重载、notify 随机唤醒一个等待线程、notifyAll 唤醒全部，这三个都要在 synchronized 块或方法里用，否则抛 IllegalMonitorStateException；finalize 在 GC 前调用，执行时机不确定且可能让对象复活，已过时，Java 18 起标记待移除。

2. == 与 equals 有什么区别？

   == 比较值：基本类型直接比数值是否相等，引用类型比的是地址，也就是两个变量是否指向同一个对象。equals 是 Object 定义的方法，默认实现和 == 一样比地址，但 String、Integer 这些类重写了它，变成比较内容是否相等。所以比较字符串或对象内容必须用 equals。注意字符串常量池：String c = "hello" 和 String d = "hello" 直接双引号赋值会复用同一个对象，== 是 true；用 new String 每次都创建新对象，== 是 false。

3. hashCode 和 equals 方法有什么关系？

   equals 判断两个对象是否相等，hashCode 帮哈希集合快速定位。三条约定：equals 为 true 时 hashCode 必须相同；hashCode 相同 equals 不一定为 true，因为不同对象可能哈希冲突；参与 equals 比较的字段不变时，同一对象多次调用 hashCode 结果不变。为什么重写 equals 必须重写 hashCode：以 HashMap 为例，查找时先按 hashCode 定位桶，再用 == 或 equals 比较，如果只重写 equals，两个业务上相等的对象哈希值可能不同，就会存过也查不到。另外对象作为 key 之后不要修改参与 equals 和 hashCode 计算的字段，否则也会查不到，常用做法是把它声明为 final。

4. Java 里 String 的常用方法有哪些？

   我常用的有这些：length 返回长度；equals 比较内容是否相等，区分大小写；substring 从指定索引截取到末尾；trim 去除首尾空白字符；replace 替换指定字符；isEmpty 判断长度是否为 0，注意 null 调用会报错，要先判空。另外 charAt、indexOf、split、contains、startsWith、toUpperCase、concat 也常用。

5. String、StringBuffer、StringBuilder 的区别和联系？

   三者都能处理字符串，区别在可变性和线程安全。String 不可变，拼接和替换都返回新对象、原对象不变，内容可以被多线程安全共享，适合存储、传递和少量拼接。StringBuilder 可变，通过 append、insert、delete 修改自身，没有同步保护，单线程内频繁拼接性能最好。StringBuffer 也可变，方法上加了 synchronized，适合多线程共享同一个可变字符串实例。要注意两点：StringBuffer 方法线程安全不等于组合操作线程安全，比如先判断长度再 append 这两步之间仍可能被插入，需要额外同步；多线程应用里的局部 StringBuilder 没有共享，不需要换成 StringBuffer。

## 十二、Java 新特性

1. Java 8 你知道有什么新特性？

   主要这些：Lambda 表达式，简化匿名内部类；函数式接口，只有一个抽象方法，可用 @FunctionalInterface 标记；Stream API，链式处理集合数据并支持并行；Optional，封装可能为 null 的值减少空指针；方法引用，如 System.out::println；接口的 default 和 static 方法；并行数组排序 Arrays.parallelSort；重复注解 @Repeatable；类型注解，可标注在泛型和类型使用处；CompletableFuture，增强异步编程。另外还有新的日期时间 API java.time 和用 Metaspace 替代永久代。

2. Lambda 表达式了解吗？

   Lambda 是一个简洁的语法，用来创建匿名函数，主要用来简化函数式接口的使用。两种写法：(参数) -> 表达式，表达式只有一条时可以用；或者 (参数) -> { 语句; }，多条语句时用大括号，有返回值要写 return。相比匿名内部类代码更短、意图更清晰，配合 Stream 做过滤映射可读性很好。它只能用于函数式接口，本质上编译器会把它转换成对应接口的实例。

3. Java 中 Stream 的 API 介绍一下

   Stream 是 Java 8 提供的处理集合的声明式 API，操作分两类：中间操作是惰性的，返回新流，比如 filter 过滤、map 映射、sorted 排序、distinct 去重、limit 限制、skip 跳过；终端操作会触发实际执行，比如 collect 收集、forEach 遍历、reduce 归约、count 计数、sum 求和。好处是代码简洁、可读性高，还能用并行流利用多核。要注意 Stream 不存储数据、不修改原集合，每个流只能用一次。

4. Stream 流的并行 API 是什么？

   是 parallelStream。它把源数据拆成多个子流多线程处理，再把结果汇总，底层用的是 ForkJoinPool 的 fork/join 框架，把大任务拆成小任务并行计算再合并。适合 CPU 密集型任务，比如大量计算。如果任务是 I/O 密集的，或者任务数远大于线程数，用并行流效果不好，而且它默认共享公共线程池，可能影响其他任务。

5. CompletableFuture 怎么用的？

   创建任务用 runAsync 执行无返回值的、supplyAsync 执行有返回值的，两者都能传自定义线程池。组合结果常用的有：thenApply 转换上一步结果、thenAccept 消费结果不返回、thenRun 不关心上一步结果、thenCompose 串联依赖的异步任务（后续操作返回 CompletableFuture 时用，避免嵌套）、thenCombine 合并两个独立任务的结果、allOf 等全部完成。异常处理用 exceptionally 提供降级值、handle 成功失败都处理并返回新结果、whenComplete 观察结果做日志清理但不改变结果。线程方面，不带 Async 的方法可能由完成上游任务的线程执行，带 Async 的可以指定线程池，耗时的阻塞任务要用独立线程池，别挤占公共 ForkJoinPool。最后 get 和 join 都会等待结果，get 要处理受检异常，join 抛 CompletionException，正确做法是先组合任务、在真正需要结果时才等待，不要启动一个就立刻 get 变成串行。

6. Java 21 新特性知道哪些？

   语言特性有三块：switch 的模式匹配 JEP 441，可以在 case 里直接用模式，更类型安全；记录模式 JEP 440，可以在 instanceof 或 switch 里直接解构 record，比如 obj instanceof Point(int x, int y)；字符串模板 JEP 430 预览版，用 STR 处理器在字符串字面量里嵌入表达式，不过这个特性在 JDK 23 被撤回重新设计了。并发特性有两块：虚拟线程，栈在堆上动态分配、挂载到少量平台载体线程执行，挂起时栈卸载到堆，可以创建海量虚拟线程，显著提升 I/O 密集应用的吞吐量；Scoped Values 范围值，在线程间共享不可变上下文数据，替代 ThreadLocal，封装性和线程安全更好。另外还引入了序列集合接口等。

## 十三、序列化

1. 怎么把一个对象从一个 JVM 转移到另一个 JVM？

   四种方式。一是序列化和反序列化，把对象写成字节流通过网络发送，另一端用 ObjectInputStream 恢复；二是消息传递机制，用 RabbitMQ、Kafka 这类消息队列或者自定义网络协议传输序列化后的数据；三是 RPC，用 gRPC、Dubbo 这类框架直接远程调用对方 JVM 上的方法；四是共享存储，把对象放进 MySQL、Redis 等共享数据库或缓存，两边读写同一份数据。前几种适合直接传对象，共享存储适合只需要共享数据、不需要对象传输的场景。

2. 序列化和反序列化让你自己实现你会怎么做？

   分五步。第一确定支持的数据范围，约定整数占几字节、字节序是什么，字符串用 UTF-8 并记录字节长度，还要能区分 null 和空串。第二定义字节流格式，消息头存魔数、协议版本、消息体长度和类型标识，消息体按字段编号、字段类型、数据长度、字段数据的顺序组织。第三实现编码和解码，序列化时按格式写字段，反序列化时先校验消息头再逐字段解析并创建对象；走 TCP 还要按长度处理粘包拆包。第四处理版本兼容，新增字段用新编号，旧版本遇到不认识的字段按长度跳过，新版本读旧数据给缺失字段默认值，删掉的编号不复用、已有字段类型不改。第五处理循环引用和输入校验，给对象分配编号避免无限递归，限制消息大小、字符串长度和嵌套深度，类型标识映射到白名单，不能按输入里的任意类名去加载。实际项目优先用成熟方案，跨语言看上 Protobuf，可读性优先用 JSON。

3. 将对象转为二进制字节流具体怎么实现？

   Java 里用 ObjectOutputStream 的 writeObject 做序列化，用 ObjectInputStream 的 readObject 做反序列化。前提是类实现 Serializable 或 Externalizable 接口，否则抛异常。只有非 static、非 transient 的成员变量参与默认序列化，transient 和 static 字段会被跳过；建议显式声明 serialVersionUID，避免类结构变化后反序列化失败。反序列化过程不会调用类的任何构造器。

## 十四、设计模式

1. volatile 和 synchronized 如何实现单例模式？

   用双重检查锁定：先判断 instance 是否为空，为空才进 synchronized 块，块内再判一次空然后创建实例。instance 必须用 volatile 修饰，作用是保证可见性和禁止指令重排序。原因是 new 一个对象分三步：分配内存、初始化对象、把引用赋给变量，如果没有 volatile，编译器或 CPU 可能重排成先赋值再初始化，其他线程在第一次判空时可能拿到一个还没初始化完的对象，用起来出问题。volatile 禁止这种重排，保证安全。实际项目中也可以用静态内部类或枚举实现单例，代码更简洁也天然线程安全。

2. 代理模式和适配器模式有什么区别？

   目的不同：代理模式关注控制对对象的访问，可以在调用前后加额外功能；适配器模式做接口转换，让本来不兼容的类能一起工作。结构不同：代理有抽象主题、真实主题、代理三个角色；适配器有目标接口、适配器、被适配者三个角色。场景不同：代理用于增强或控制访问，比如远程代理、权限代理、延迟加载；适配器用于兼容已有接口，比如给老系统包一层新接口。

3. 责任链模式使用场景是什么？

   核心场景是一个请求需要多个独立的处理逻辑依次承接，同时不想让发起方和所有处理者强耦合，并且处理流程需要能灵活调整。典型例子是接口请求校验：先查登录状态，再验 token，再确认权限，最后限流，每个校验封装成一个处理节点，用 setNext 串成链，发起方只调用第一个节点。这样不同接口按需组装不同的链路，加减步骤只改组装代码，不用动各节点，避免在每个接口里写一堆 if-else，后续改规则也不用全量回归。

4. 介绍一下策略模式和责任链模式，分别用在哪些场景？

   两者都是行为型模式，目的都是消除复杂的 if-else 或 switch，让系统容易扩展。策略模式定义一系列算法，各自封装成实现同一接口的类，可以互相替换，运行时动态选择。比如电商支付模块，支付宝、微信、银行卡各自的调用和加密逻辑完全不同，但上层只调统一的支付方法。适用于需要在多种算法间动态切换、希望算法变化不影响客户端的场景。责任链模式把多个处理者连成一条链，请求沿链传递直到被某个节点处理，发送者不需要知道最终由谁处理。比如请假审批，经理没权限就上报总监、总监没权限再上报总经理；还有 Web 框架的过滤器链。适用于多个对象都可能处理同一请求、发送者和接收者要解耦、处理链需要动态调整的场景。

## 十五、I/O

1. Java 怎么实现网络 IO 高并发编程？

   用 Java NIO，它是同步非阻塞的 I/O 模型，也是 I/O 多路复用的基础。传统 BIO 里 socket.read 如果缓冲区没数据会一直阻塞，要并发处理多个客户端就得为每个连接开一个线程，连接数一多线程数暴涨、性能急剧下降。NIO 基于多路复用，可以用少量线程管理成千上万的连接，适合连接数多但每个连接只发少量数据的场景，比如聊天服务器。实际项目中一般直接用 Netty 这类封装好的框架。

2. BIO、NIO、AIO 区别是什么？

   BIO 是传统 java.io，基于流模型，同步阻塞，读写动作完成前线程一直阻塞，调用是可靠的线性顺序，代码简单直观但效率和扩展性差，容易成为瓶颈。NIO 是 Java 1.4 引入的 java.nio，提供 Channel、Buffer、Selector，可以构建多路复用的同步非阻塞 IO，更接近操作系统底层的高性能数据操作。AIO 也叫 NIO.2，Java 1.7 引入，是异步非阻塞，基于事件和回调，应用发起操作后立即返回，处理完成后由操作系统通知线程。

3. NIO 是怎么实现的？

   靠三个核心组件。Channel 负责数据读写，比如 SocketChannel，本身可以工作在阻塞或非阻塞模式，配合 Selector 时必须设成非阻塞；Buffer 负责存放数据，从 Channel 读的数据先进 Buffer，写数据时把 Buffer 内容写入 Channel；Selector 负责监听多个 Channel 的就绪事件，比如新连接到来、可读、可写。服务器流程是：ServerSocketChannel 设非阻塞、注册到 Selector 监听连接事件；accept 到客户端后把 SocketChannel 也设非阻塞、注册读事件；线程调用 select 等待事件就绪；select 返回后遍历就绪事件做 accept、read 或 write。这里要澄清两个概念：非阻塞指通道的读写不会为等数据就绪而一直阻塞，比如 read 没数据可能返回 0，但 select 本身可以阻塞，selectNow 才立即返回；同步指就绪后仍要应用线程自己调用 read、write，Selector 只通知可以读写了，不会替你把数据读好。另外一次 read 可能只读到一部分数据，程序要自己保留未处理的数据继续处理。

4. 你知道有哪个框架用到 NIO 了吗？

   典型是 Netty。它封装了网络通信能力，不用自己写 Selector 循环和维护连接状态。它通过 NioEventLoopGroup 管理一组 NioEventLoop，每个 EventLoop 通常由一个线程跑事件循环，用 Selector 监听多个 Channel 的就绪事件，再通过 ChannelPipeline 和 ChannelHandler 把事件交给解码、业务处理、编码等逻辑。TCP 服务通常配两组 EventLoopGroup，bossGroup 负责接收连接，workerGroup 负责连接的读写。要区分 Netty 的 NIO 传输和原生 epoll 传输：NioEventLoopGroup 依赖 Java NIO 的 Selector，EpollEventLoopGroup 走 Linux 原生 epoll、不经过 Selector，需要原生依赖。线程数取决于 EventLoopGroup 配置，不是一个 EventLoop 就等于整个服务一个线程。另外不要在 EventLoop 里做耗时的数据库查询或阻塞 RPC，会影响它管理的其他连接，应该交给业务线程池。

## 十六、其他

1. 有一个学生类，想按照分数排序，再按学号排序，应该怎么做？

   让 Student 实现 `Comparable<Student>` 接口并重写 compareTo 方法：先比较分数，分数不同时按分数降序返回，分数相同时再用 Integer.compare 按学号升序返回。然后在需要排序的地方调用 Collections.sort 或 list.sort 即可。如果排序规则不固定、需要运行时切换，用 Comparator 更灵活，比如 Comparator.comparing(Student::getScore).reversed().thenComparing(Student::getId)，语义也更清晰。

2. Native 方法解释一下

   native 方法是用 native 关键字声明、实现由 C/C++ 等本地代码提供的方法，Java 类里只有声明没有方法体。它用来调用 Java 做不到或者性能不够的本地能力。实现步骤：用 javac -h 生成 JNI 头文件，注意 javah 工具从 Java 9 起废弃、Java 10 已移除；按头文件在 C/C++ 里实现方法，编译成 Windows 的 DLL 或 Linux 的 SO；再用 System.loadLibrary 加载本地库，JVM 就能找到并调用。

3. Java 进程是怎么跟操作系统交互的？

   JVM 本身就是一个操作系统进程，所以 Java 和系统的交互本质上是 JVM 这个中间层在完成。内存方面，JVM 启动时通过 mmap、brk 这类系统调用向操作系统申请堆和栈内存。线程方面，平台线程和操作系统原生线程是一对一，Linux 上用 pthread_create 创建，调度和 synchronized 底层的互斥锁都由操作系统管理；Java 21 的虚拟线程属于用户态，由 JVM 调度、复用到少量载体线程上。IO 方面，文件读写最终调用 read、write，网络调用 socket、bind、listen，NIO 底层在 Linux 上是 epoll、Windows 上是 IOCP。JNI 是另一条通道，需要本地能力时通过它调用 C/C++ 再直接调系统 API。还有信号处理，比如 kill 发 SIGTERM 给 Java 进程，JVM 捕获后执行关闭钩子。从用户态和内核态看，IO、网络操作都要切换状态，切换有开销，JVM 会用缓冲区等手段减少系统调用次数；JVM 屏蔽了平台差异，但在每个平台上都要适配对应的系统调用。
